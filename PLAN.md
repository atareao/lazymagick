# lazymagick Phase 3 — Polish & Ship Implementation Plan

## Objetivo

Deliver lazymagick v0.1.0 by adding a project README, CI pipeline, shell completions, and help/docs improvements — all without breaking any existing functionality.

## Arquitectura

Four independent deliverables, each touching distinct parts of the codebase:

1. **README.md** — single Markdown file at project root (no tool changes)
2. **CI (GitHub Actions)** — `.github/workflows/ci.yml` (infrastructure only)
3. **Shell completions** — `clap_complete` integration in `src/cli.rs` + `src/main.rs`
4. **Man page / help** — `--help` output is already generated by clap-derive; man page can be generated via `clap_mangen` as a build step or manually

No dependencies between tasks. All 62 existing tests must continue to pass, clippy must remain clean, and `cargo fmt` (2024 edition) must format without diffs.

## Tech Stack

- **Rust**: edition 2024, rustc ≥ 1.85
- **TUI**: ratatui 0.30, crossterm 0.28
- **CLI**: clap 4 with derive
- **CI**: GitHub Actions (ubuntu-latest, macos-latest)
- **Completions**: clap_complete 4

## Global Constraints

1. **Edition 2024**: `gen` is a reserved keyword. `unsafe` blocks in `static`/`const` initializers are now allowed. `impl Trait` in return position is `use<..>` syntax. Always run `cargo fmt` after edits.
2. **All 62 existing tests must continue to pass** (`cargo test`).
3. **clippy must remain clean** (`cargo clippy -- -D warnings`).
4. **`cargo fmt`** must produce no diffs (edition 2024 style with different formatting rules).
5. **No breaking changes** to existing CLI flags, TUI keybindings, recipe format, or public API.
6. **`magick` must be on `$PATH`** — this is a runtime prerequisite, not something CI should mock.
7. **All new files** must be tracked in git.

      ```yaml
      name: CI

      on:
        push:
          branches: [main]
        pull_request:
          branches: [main]

      env:
        CARGO_TERM_COLOR: always

      jobs:
        test:
          strategy:
            matrix:
              os: [ubuntu-latest, macos-latest]
          runs-on: ${{ matrix.os }}

          steps:
            - uses: actions/checkout@v4

            - name: Install Rust toolchain (stable, ≥ 1.85)
              uses: dtolnay/rust-toolchain@stable
              with:
                toolchain: stable
                components: rustfmt, clippy

            - name: Install ImageMagick (Linux)
              if: runner.os == 'Linux'
              run: sudo apt-get update && sudo apt-get install -y imagemagick

            - name: Install ImageMagick (macOS)
              if: runner.os == 'macOS'
              run: brew install imagemagick

            - name: Check formatting
              run: cargo fmt --check

            - name: Clippy
              run: cargo clippy -- -D warnings

            - name: Test
              run: cargo test
      ```

## Category B: Optional Improvements (Low Priority — Plan for Later)

These are deferred to a future phase and are documented here for reference only.

### B.1: Log Panel Scrolling

**Context:** The `LogPanel` currently has no scroll state. `App::log_entries` grows unboundedly. Users cannot scroll back to see earlier entries.

**Approach:**
- Add `log_scroll: usize` field to `App`
- Add `LogScroll` variant or reuse existing mode
- Cap `log_entries` at N entries (e.g., 1000), dropping oldest
- Render a scrollable viewport into the log panel
- Keys: `j`/`k` or `Ctrl+u`/`Ctrl+d` when focus is on log panel

**Files:** `src/app.rs`, `src/ui/log_panel.rs`

### B.2: Recipe Editor from TUI

**Context:** Currently, editing recipes requires manually editing TOML files outside lazymagick. The `E` key exports built-ins to `~/.config/lazymagick/recipes/` but does not open an editor.

**Approach:**
- Add a "create/edit recipe" popup with form fields (name, description, output_ext, stages, formats)
- Or shell out to `$EDITOR` for the TOML file
- Reload recipes after editing

**Files:** `src/ui/` (new popup module), `src/app.rs`

### B.3: Integration Tests

**Context:** Current tests cover unit-level logic (parsing, command building, path resolution) but never invoke the real `magick` binary.

**Approach:**
- Create `tests/integration/` directory
- Use `tempfile` to create test images (via ImageMagick or raw bytes)
- Test the full pipeline: recipe loading → command building → execution → output validation
- Gate with `#[cfg(feature = "integration-tests")]` or `#[ignore]` to avoid requiring ImageMagick in all environments

**Files:** `tests/integration/main_test.rs`

### B.4: Cargo Dist / Homebrew Publishing

**Context:** Currently, users install via `cargo install lazymagick`. Official distribution channels improve discoverability.

**Approach:**
- Add `cargo-dist` configuration for automated release builds
- Set up a Homebrew tap (`lazymagick/homebrew-tap`) or submit to `homebrew-core`
- Publish to `crates.io` with `cargo publish`

**Files:** `.github/workflows/release.yml` (generated by cargo-dist)

### B.5: More Recipes

**Context:** Currently 42 built-in recipes. The Instagram-style filter set is a strong differentiator.

**Approach:**
- Add more Instagram-style filters: `sierra`, `moon`, `hudson`, `perpetua`, `rise`, `brannan`, `hefe`, `sutro`, `kelvin`, `lark`, `reyes`, `stinson`, `vesper`
- Add utility recipes: `polaroid` (instant frame), `rounded corners`, `glitch` (offset RGB channels), `cinematic` (2.35:1 letterbox), `duotone`

**Files:** `recipes/builtins.toml`
